## Request and source contract

Account for every original requested clause and its exact question span. Support
fronted order departure questions, a released request in the bounded For-context,
working-day departure, the current-guide qualifier and the explicit hold-overrides
question. Unknown clauses remain terminal refusals. Maximum three facets; each
uses its own independently embedded, answer-free query and aligned body cosines.

Keep legacy exact document identity and typed-ticket ambiguity checks. Only the
new forms may use a unique complete-token filename prefix for a shortened name.
A current-guide request additionally requires a literal current dispatch-guide
heading with the same entity prefix; archived/superseded headings cannot qualify.
No current heading, duplicate current guides or multiple prefix candidates means
refusal. An anonymous order question requires one unique document with an
applicable order relation, across the entire supplied corpus; all facets must be
supported by that same document. Do not select scope from retrieval rank.

Extend literal policy schemas for optional `on`, released requests that `are
shipped`, an entity-bound `At ENTITY, orders ...` prefix, and holds that `prevent
departure` or `are in effect` (singular `is in effect` in the source). Preserve
before/equality/exclusive-after, day units, operational types, complete exceptions,
conflicting/denied/conditional/repeated-span vetoes and all-or-refuse accounting.
Source output must remain an unchanged original sentence bound to actual body
metadata. No fabricated similarity, answer generation or old-candidate fallback
inside clock ownership. Outside scope and lexical Comparison exports stay frozen.
