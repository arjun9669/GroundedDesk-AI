## Structured request and relation changes

Parse ticket as operational order type separately from the full named entity,
retaining the original raw context and bare-order alternative identity. Never
strip arbitrary trailing name words. A typed parse must match exactly one named
source; if an alternative bare entity exists, refuse rather than silently select.
Names containing Ticket/Order remain literal; unresolved names refuse. Qualified
legacy contexts and v41 behavior outside governed scope remain unchanged.

Add scoped `what can hold it back` only after a fully accounted departure facet
in the same entity/time context. Preserve whole-question accounting; unknown,
actor/password/payment/vehicle/mixed requests still refuse. No inherited answer
fallback for an unresolved governed request.

Represent explicit declarative `Ticket orders released/cleared ... leave/depart/
ship on DAY` and imperative `Release ticket orders ... for departure on DAY` as
the same bounded relation fields:order type, operator, time, original day unit,
full optional hold and literal span. Match ticket facets to explicit ticket-order
relations; do not infer applicability from generic purchases/orders or time-only
text. Preserve before/exclusive-after/inclusive equality, every exception and exact
displayed quotes. Hold remains active is already supported, not a new synonym fix.
Keep existing contradiction/negative/conditional/repeated-evidence vetoes; bounded
negation projections can veto only and never create an authorizing quote.
