# Answer coverage experiment — frozen development protocol

Frozen before implementation or new outputs. Base commit 28a39b9992eb5deda69eb5c076539efe484b3a1f. Production remains r44. No release is authorized by this development gate alone.

Reuse the unchanged Retrieval Quality 28 documents, questions, answer key and exact displayed-quotation rubric. Preserve both original 16/7/5 fixed-window and 19/7/2 section-window results. This is a known, self-authored development regression, not unseen independent accuracy.

Predeclared candidate: wrap existing extractive answer selection without altering MiniLM, BM25, chunking, RRF or thresholds. Never rescue an existing refusal. For an accepted quote anchored in a Markdown level-two section, recover literal complete sentences only from its local paragraph; never cross a heading, blank paragraph boundary or labeled commentary line. Limit contiguous quotations to 620 characters and three sentences. Permit an explicitly asked condition/event branch, or immediately adjacent missing facets/exception clauses. Do not append qualifications to single-fact requests indiscriminately. Literal printed before/at-or-after clock rules can be selected by a numeric time in the question only with matching subject terms and a unique applicable local branch; no inferred departure sentence. Trigger-event clauses require event and object overlap. No source names, case identifiers, benchmark values or expected sentences in algorithm rules.

For an explicit multi-document question, allow separately anchored answers from up to three actually ranked, explicitly named documents. Infer names conservatively from distinctive filename terms, respect explicit current/archived qualifiers, and reject ambiguous aliases. No searches outside ranked candidates. Preserve source filenames, source text, citation numbering and contiguous source spans. No generative model, entailment claim, arbitrary sentence concatenation or mock embeddings.

Evaluate fixed windows + coverage against original fixed baseline. Also evaluate unchanged section windows + coverage against original section baseline to distinguish answer-selection effects from chunking. Use actual installed Chrome and actual local Xenova/all-MiniLM-L6-v2 q8 WASM with Qwen off. Preserve each candidate output once in an exclusive new directory. Record any infrastructure failure; no replacement of failed output. Instrumented browser-module outputs are labeled separately from the historical main-UI captures. No candidate UI feature is claimed.

Gate: fixed-window strict PASS >16, no original PASS regression, no increased false acceptance/refusal, all quotation provenance valid; section combined PASS >=19 with no original section PASS regression. Run existing unit regression suites and available frozen Cobalt16 real-model controls before any release consideration. If wider original benchmark packs are available, preserve instrumented real-model controls separately; do not relabel lexical unit tests as MiniLM results. No tuning after candidate benchmark outputs; failures inform a later separately frozen experiment.

An independent release evaluation needs externally controlled unseen material. A new self-authored fixture or this in-sample run cannot meet that gate. Production remains unchanged in this experiment regardless of development score.
