# V40 bounded dispatch grammar protocol

Authorized 2026-10-20 after the Lumen32 v39 failure investigation. Commit this
protocol before implementation. Candidate: `coverage-v40-dispatch-grammar`.
Production remains 5.6/r44. Preserve frozen v39, inputs, native criteria and every
first result, including Lumen32 v39's 31 PASS / 1 FAIL in both variants.

## Change and unchanged guards

Implement an isolated v40 adapter/contract. Add positive `should` departure
questions within the existing named/time context; explicit `departure moves to`,
`following` service/operating/business/working day and `hold is (still) active`
source forms. Keep literal quotations and cutoff inequalities. Never use an older
answer as fallback for an unresolved governed question. Outside-scope requests
and Comparison retain v39 behavior.

Preserve whole-question facet accounting, unique named document identity,
negative/conditional/conflicting/repeated evidence vetoes, three-source/620-character
limits, literal bounds and finite aligned body/facet evidence. Unknown/mixed
clauses, unsupported actors/passwords/vehicles and negated questions refuse.
No calendar-date inference, general paraphrase acceptance or threshold changes.

## Engineering gate

Through the public entry point test original L04 and varied names/cutoffs,
does/will/should, individual/composed source forms, before/equal/after, missing
holds, qualified/negative/proposed conflicts, identity/repetition/citation limits,
invalid or misaligned facet evidence and unsupported/mixed requests. Preserve
all existing tests, including V23/V27 controls. Synthetic cosine fixtures are
engineering controls, never actual-model evidence. Run Node 22+ unit tests,
strict 28-case Keyword evaluation and applicable browser startup checks.

## Freeze and actual-model gate

After engineering passes, publish a new freeze of candidate, planner, transitive
imports, runner, scorer, environment, original keys/rubrics/source bytes and
historical first scores BEFORE asking model questions. Use a new evidence path
with exclusive writes. Capture all 96 exposed cases (Vela32, Prism32, Lumen32;
84 actual MiniLM Hybrid and 12 lexical Comparisons), then score each 32-case pack
separately using unchanged native automated criteria. Question retries: zero.

Compute fresh actual MiniLM source/query/legacy-facet/v40 planner-facet vectors.
Compute paired v39 planner queries/vectors separately and align them independently;
L04's old zero-facet capture cannot substitute for new vectors. Save actual UI
outputs and pre-candidate vectors before calling experimental adapters. Preserve
r44 UI reproduction checks and module identity proofs. Qwen remains off.

Both fixed and section variants must reach 32 PASS / 0 PARTIAL / 0 FAIL per pack,
repair L04, preserve every historical/paired PASS and introduce no false accepts
or false refusals. Review literal relevance/completeness after automated scoring;
retain native grades if review downgrades a case, and stop. Preserve paired v39's
Lumen failure as a historical result rather than requiring it to become a pass.
Any required check failure stops work for user review before retries, further
implementation, committing or publishing.

## Interpretation and remaining work

These are 96 previously exposed distinct cases, not 192 independent observations,
fresh confirmation, a pooled general accuracy estimate or the full 771-case gate.
The verified inventory totals 668 cases; 103 cases and the original combined
configuration are unavailable. Other verified packs (starting with Hearth32),
full regression, prospective confirmation and integration/product/release gates
remain outstanding. No live adoption is authorized by this protocol.
